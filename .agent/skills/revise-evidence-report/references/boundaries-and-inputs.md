# Boundaries and Inputs

Revise an existing report and its delivery artifacts. Preserve the report's accepted subject, evidence base, and user-owned edits.

## Start from the smallest usable input

Begin when the caller supplies:

- an editable report source, preferably Markdown; and
- the sources, data summaries, or evidence artifacts needed to check its material claims.

Use richer inputs when available:

- evidence or result-bundle manifests and digests;
- analysis code, logs, tables, and calculation records;
- an issue or decision log from an earlier review round;
- task-local audience, tone, structure, and delivery requirements;
- publication-ready figure assets, figure specifications, data digests, and a figure manifest;
- an approved stylesheet or delivery template.

Accept equivalent provenance when a formal package is unavailable. Mark unverifiable details as findings and produce a reviewable draft when the supported content still stands.

## Apply risk-driven assurance

Use a short editorial pass for low-risk prose improvements whose claims and sources are already clear. Add a structured evidence map, issue ledger, independent calculation checks, and page-level delivery review as numerical, scientific, legal, operational, or publication risk increases.

Treat these as material pause conditions:

- a central claim cannot be supported or narrowed responsibly;
- two authoritative sources conflict in a way that changes the conclusion;
- a requested revision needs a substantive user choice;
- required source access, private data authority, or publication authority is missing.

Treat absent optional metadata, non-central provenance gaps, or preferred formatting as warnings. Continue with explicit draft status and scoped findings.

## Keep responsibilities focused

Audit and revise report content, evidence traceability, metric and figure explanations, figure embedding, document rendering, and final artifact QA.

Consume the accepted research brief, protocol, result bundle, analysis, and figure bundle as inputs. Route new research questions and hypotheses to a formulation workflow; route experimental redesign to an experiment-design workflow; route new or corrected plots to a figure-production workflow.

Do not execute experiments or silently alter source data, statistical models, frozen protocols, figure data, or figure specifications while revising prose.

## Deliver explicit states

Use `DRAFT` when material checks or user decisions remain, `UNDER_REVIEW` for disputed passages, and `ACCEPTED` only for decisions the user has approved. A delivery may contain accepted sections and scoped draft findings at the same time.

Return the editable source, requested HTML/PDF artifacts, render manifest, QA result, and only the unresolved matters that affect safe interpretation or acceptance.
